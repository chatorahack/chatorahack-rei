# 受け取った資料の扱い（`_inbox/` → `_archive/`）

- **誰が実行するか**：置くのは人。処理（読んで書き移す）は AI が手伝う。`_archive/` へ移すのは、人に確かめてから
- **何が起きるか**：受け取った資料（メール・文書・添付・人から渡されたファイル）を、受け取ったまま `_inbox/` に置いておける。起動のたびに、`_inbox/` に処理していない資料があれば知らせる（`session-start.sh`）
- 流れは、仕事の整理術の定番（GTD）の「受け取る → 処理する → 保管する」に合わせた

## 流れ

1. **受け取る**：人が、受け取ったままの資料を `_inbox/` に置く（名前を付け直さなくてよい）
2. **処理する**：AI が開いて中身を見て、要ることを正式な場所に書く
   - まだやっていない作業 → `ledger/task_log.md`
   - 決めたこと → `decisions/`
   - 知識・手順 → `docs/`
3. **保管する**：人に確かめてから、元の資料を `_archive/` の下のフォルダへ移す（下の名前）。書いた行には「元の資料：`_archive/〇〇/`」と1行残す
4. `_inbox/` に `_about.txt` しか無ければ、全部処理済み

## `_archive/` の名前

`_archive/YYYYMMDD-TASK-N_件名/`（例：`_archive/20260101-TASK-1_sample/`）。台帳の行に結び付かない資料（参考に渡されただけのもの）は、`TASK-N` の代わりに「参考」と書く（`_archive/20260101-参考_sample/`）。

| 決まり | 理由 |
|---|---|
| 中のファイル名は、元の名前のまま変えない | 送ってきた人と同じ名前で話せる。手を加えていない証拠になる |
| 中身を直さない・上書きしない。直した版は正式な場所に置く | 元の資料は、原文を確かめるためのもの |
| 同じ名前が重なったら、末尾に `-2` を付ける | 上書きを防ぐ |
| フォルダ名に人や相手先の名前を入れない | フォルダ名は台帳に書き写され、残るため |
| 消さない。「終わったら消す」約束があるものは従い、消したことを台帳に書く | 原文を後で確かめられるように。契約は守る |
| パスワード・キーが書かれた資料は、`_inbox/` にも `_archive/` にも置かない。届いたら `.env` など秘密の置き場に移し、値は台帳に書かない | 秘密を広い場所に残さない |

## git

`_inbox/`・`_archive/` は git に入れない（`.gitignore`。他人の資料や個人情報を含みうるため）。`_about.txt` だけは入れる。退避するときは、git とは別に `_archive/` も退避先に含める（`docs/howto/backup.md`）。
