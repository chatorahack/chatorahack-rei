# セカンドオピニオン（別のモデルの検証）を頼み、全文を保存する

- **誰が実行するか**：AI（頼むこと・保存すること）、人間（採否を決めること）
- **前提**：頼む先のモデルを使える（Claude Codeなら、サブエージェントでモデルを指定する）
- **いつ**：決定を書く前、公開前、大きな方針を決めたあと

## 手順
1. 頼む文を作る：何を検証してほしいか、読むべきファイル（**方針の文書だけでなく、進捗の台帳も**渡す。渡さないと、進み具合を取り違える）、
   読まないもの（機密・個人の設定）、「批判だけでなく既存の標準・道具での代わりの案も出す」「ツールの挙動を断言するときは公式の根拠か『未確認』を書く」
2. 頼む。作業セッションの説明文（「〜しました」）は渡さず、ファイルそのものを読ませる
3. 返ってきた全文を`ledger/consultations/YYYY-MM-DD-NN-<内容>.md`に保存する（依頼文と回答の両方）。**保存する前に、個人を特定できる情報が
   含まれていないか確かめる**
4. 指摘のうち確かめられるものを、自分でコマンド・公式の文書で確かめる（鵜呑みにしない）
5. 保存したファイルの末尾に「頼んだ側の検証と判定」（確認済み／疑わしい／誤認と、その根拠）を書き足す
6. 人間に要点と判定を示し、採否を決めてもらう。自分の誤りの型が見つかったら、次から自分で確かめる項目として記録する

## 効いたことの確かめ方
保存したファイルに、依頼文・回答・頼んだ側の判定の3つがそろっている。採否が決定（`decisions/`）か台帳に書かれている。

## 戻し方
採らなかった指摘は、判定とその理由を残したまま置いておく（消さない）。
