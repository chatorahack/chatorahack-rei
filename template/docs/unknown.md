# 未知を見つけたとき

人間が「初めて」「分からない」と言ったとき、またはAI自身が知らないことに出会ったときの手順。

0. **持ち物の棚卸し（最初に）**：作業フォルダのルートを一覧し、REI の雛形に無いもの＝**人間が渡した持ち物**（資料・指された場所）を名指しで答えに書く（例：「渡されたもの：`notes.md`、`data/`」）。無ければ「渡されたものは無い」と書く。簡易診断（5. の 2.）は、この持ち物を**開いて見たもの**を根拠にする。**開いていないのに「無い・空」と書かない**（未確認の否定。開かずに答えると誤る）。SessionStart の hook が「人が渡したもの：…」を知らせるので、まずそれを開く
1. **目的を確かめる**：何をしたいのか、何のためか、を人間の言葉で1行にする（`START.md`・台帳の入口に書く）
2. **既存の記録を確かめる（さっと）**：このプロジェクトの`handoff.md`・`decisions/`・`ledger/`に、同じ話や前の判断が無いかを見る。**空なら「無い」で即進む**。ここで時間をかけて最初の答えを遅らせない（下の「答えを先に、記録はあとで」）
3. **知っている／知らないを分ける**：分かっていること、分からないことを並べる。分からないことは「分かりません。調べます」と言う
4. **既存を探す**：まず`docs/domains/〈分野〉.md`（分野の地図）を引く。そのうえで次の2つを、それぞれ探す（地図に無い・足りない種類は Web で）。片方だけで終わらない。見つからなければ、その事実を言う
   - (a) **その分野の決まり**：公式の規定・要項・標準・法令。人間が書いた本人の状況（今していること・使っているもの・経験など）と決まり（その分野の条件・資格・利用規約など）を突き合わせ、当たりそうなものは先に知らせる。原文で確かめるのは本人の状況に関わる上位3件まで。残りは「どれを使うか決まってから原文で確かめる」と言う（全部を原文で確かめると、答えるまでに時間がかかりすぎるため）
   - (b) **その分野の定番・型・先行例・道具**：同じ目的の製品・サービス・OSS、定番の型や手法、先行する作品・事例、入門の定番（本・講座）、公開・共有の場。`docs/glossary.md`に無い分野なら、辞書で終わらず Web で「〈分野〉 定番」「〈分野〉 型」「〈分野〉 入門」「〈作りたいもの〉 アプリ／ツール」を引く
   - **道具・権限が足りないとき**：Web検索などの道具が使えず調べられないときも、そこで止まらない。**手元の資料（渡されたファイル・台帳・設定）でできる簡易点検を先に行い**、危険や要点をざっくり出す。道具が要る部分は「権限をもらえれば詳しく調べます」と分けてお願いする（道具が無いことを、拾えるはずのことを素通りする理由にしない。`policy.md` 1.）
5. **つないで渡す（答えはこの順で、先頭から）**：
   1. **分野の地図（先に。台帳を読まなくても出せる。ただし持ち物〔0.〕は簡易診断の前に必ず開く）**：その分野が何か・**業界標準の仕組み**・一般的な進め方を短く説明する（数行）。(b) の定番・型・先行例・道具はここで「世界の地図」として固有名詞で示す——やることの羅列ではなく「普通はこう回っている」という説明として。独自の手順は作らず定番に沿い、何を参照したか1行書く。REI は「初めての人を知っている世界につなぐ案内役」＝まず世界の地図を渡す（タスクの一覧だけを渡さない）。**相手の習熟に合わせて厚みを変える（fading、`policy.md` 1.）**：初めて＝厚く、慣れている様子＝地図は1行に畳んで聞かれた点へ。危険と「人に返す」は畳まない
   2. **簡易診断**：そのうえで、手元の資料で見た範囲の相手の状況（危険・要点）を数点、落ち着いて示す。「完璧な診断ではない」旨を1行添える。詳しく調べるのに道具・権限・情報が要るなら、**この診断に添えて**「手持ちで見た範囲はこれ／詳しくは○○が要る」と分けてお願いする
   3. **最初の一歩**：具体の一歩を1〜2個に絞る。自分で作る部分と既存で足りる部分を分ける。決めるのは人間で、採用・方針・元に戻せない操作は人間に返す
   全体に：「これは○○に近いです」と根拠と不確かさ（3ラベル）を付ける。判断待ちを返すときも、決まる前に進められる既存の入口（定番・型・道具・先行例）は同じ答えに並べる（分かれ道の手前で中身を止めない）。**1つの答えで人間に返す問いは最大2つ**。それ以上は大事な順に2つにし、残りは次の答えに回す（一度に多く聞くと、人が答えにくくなる）
6. **決まったら残す**：人間が選んだものと理由を`decisions/`か台帳に書く。次も使いそうな考え方は、辞書に足すかを人間に聞く。見せた既存のものは、`docs/domains/README.md`の「足し方」で1回だけ聞き、人間が残すと言ったものを分野の地図に足す

**答えを先に、記録はあとで**：最初の答え（特に 5. の「分野の地図」）より先に、台帳の読み書き（記録の確認・起票）で人間を待たせない。地図は一般知識で即出せる。起票・更新は答えを返したあとでよい（人を待たせないため）。

情報源の目安：一次情報・公式仕様 → 標準化団体・公的機関 → 公式文書 → 論文 → 信頼できる解説 → Wiki → AIの推測。
定番・型・先行例は、提唱者の原典・公式の講座・実在の作品や製品の公式ページを優先する。
AIが生成した内容だけを根拠にしない。
