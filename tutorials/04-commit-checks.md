# 4. コミット前の点検

前もって済ませること：[チュートリアルの入口](README.md)の「始める前に」。

**覚えること**：コミットのたびに、決定ファイルの書き換え・見えない制御文字・個人情報（登録した語）・REI の受け取りの記録を機械が確かめます。git が動かす点検なので、Claude Code の外で人がコミットするときも効きます（「始め方」で `git config core.hooksPath .githooks` を設定してあることが前提です）。`git commit --no-verify` を付けると飛ばせるので、強制ではありません（気づくための仕組みです）。

**試すこと**（Git Bash で）：見えない制御文字（ベルの文字）を入れたファイルをコミットしてみます。

```sh
printf '試し\a\n' > note.txt
git add note.txt
git commit -m "試し"
```

**起きること**：［機械］コミットが止まり、`[制御文字] note.txt：足した行に、見えない制御文字が 1 文字入っています` のような知らせが出ます（その前に、決定ファイルの点検の `OK` の行も出ます）。

**片付け**（1行目で git の追跡から外し、2行目でファイルそのものを消します）：

```sh
git rm --cached note.txt
rm note.txt
```

**個人情報の点検も試すなら**（表を作った人だけ）：リポジトリの外に、止めたい語を1行ずつ書いたファイル（表）を作り、作り話の名前を1つだけ入れます（手順は `docs/howto/pii-check.md`。例：`見本 花子==>{{PERSON}}`）。表が無いときは、個人情報の点検は注意を出すだけで、コミットは止まりません。

```sh
echo "担当：見本 花子" > note.txt
git add note.txt
git commit -m "試し"
```

［機械］コミットが止まり、ファイル名と行番号だけが出ます（名前そのものは出ません）。片付けは上と同じです。試しのために表に足した作り話の名前は、終わったら表から消してください。

**点検そのものの試し**：`bash scripts/test-check-pii.sh` と `bash scripts/test-check-control-chars.sh` を実行して、1つ目は「不合格 0」、2つ目は「全部期待どおり」と出れば動いています（[README](../README.md) の「点検の試し方」）。
