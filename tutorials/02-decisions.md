# 2. 決めたことを残して、あとで覆す

前もって済ませること：[チュートリアルの入口](README.md)の「始める前に」。

**覚えること**：決めたことは `decisions/` に残り、書き換えずに新しい番号で覆します。

**打つ言葉**：

```text
ページの文字の色は黒にします。これは決定として残してください。
```

**起きること**：［AI］`decisions/0001-…md` ができます（決めた人・決めたこと・理由・覆す条件）。

**ここで一度コミットします**（Git Bash で）。書き換えの確認は、git に入った（`git add` で追跡を始めた）決定ファイルにだけ働くためです。

```sh
git add decisions
git commit -m "決定 0001"
```

［機械］`[REI] 注意：個人情報のパターン表…が無いため…` という2行が出ても、ほかの点検で止まっていなければ、コミットはできています（個人情報の表を作っていないときの知らせです。[4. コミット前の点検](04-commit-checks.md)で触れます）。Windows で出る `LF will be replaced by CRLF` の警告も無害です。

**続けて打つ言葉**：

```text
やっぱり文字の色は濃い灰色にします。
```

**起きること**：

- ［AI］0001 を書き換えずに `decisions/0002-…md` が足され、0001 を覆すと書かれます
- ［機械］AI が 0001 を直接書き換えようとすると、確認の画面に `[REI decisions-guard] 既存の決定ファイル（decisions/0001-…）への直接編集です` という理由が出ます。この理由が出たときだけ、許さない側を選び、「新しい番号で足してください」と伝えます。理由が `[REI …]` で始まらない確認（0002 を新しく作るときなど）は、Claude Code のふつうの確認なので、許してかまいません。`[REI decisions-bash-guard]` と出たときは、AI がコマンドで `decisions/` に書こうとしています。「編集の道具で、新しい番号のファイルとして作ってください」と伝えます

**確かめる場所**：`decisions/` に2つのファイルがあり、0001 の中身が変わっていないこと。

確認の画面を見てみたいときは、「0001 を直接書き換えてください」と頼むと、`[REI decisions-guard]` の確認が出ます（許さない側を選びます）。
