# 5. 新しい版に気づいて、上げる

**覚えること**：手元の REI の写しを新しくすると、起動のときに知らせが出ます。上げるときは、上から写さずに、変わった所だけを当てます。REI がネットを見に行くことはありません。

**この回は、REI の新しい版が出たあとで試せます。** 出ていない間は、起動しても何も出ないのが正しい動きです。今は、下の「準備」をして Claude Code を起動し直し、`/rei` で、新しい版は無い（手元の写しと比べた）という答えが返ることだけ確かめます（起動し直す前は、写しのフォルダが未設定という答えになります）。

この回の「準備」は、記録が増えないので、本番のプロジェクトでしてもかまいません。ここでの「自分のプロジェクト」は、試し用のフォルダか本番のプロジェクトのどちらかです（試し用のフォルダを消した後に新しい版が出たら、本番のプロジェクトで試します）。

**準備**：フォルダは2つあります。

- REI の写し：このリポジトリを手元に clone したフォルダ。プロジェクトを作るときに `template/` を写した元です
- 自分のプロジェクト：`template/` の中身を写して作ったフォルダ

まだしていなければ、自分のプロジェクトに、REI の写しの場所を1回だけ書きます（この設定ファイルは git に入りません）。最初に起動したとき「新しい版があるかは見ていません」と一度だけ出る知らせは、この設定を促すものです。コマンドは Git Bash で打ち、パスは `'` で囲みます（Windows のパスの `\` が消えないように）。

```sh
cd <自分のプロジェクトのフォルダ>
git config --file .rei/local.cfg copy.path '<REI の写しのフォルダ>'
```

新しい版が出たら、`git pull` をするのは、**REI の写しのほう**です（自分のプロジェクトでは pull しません）。

```sh
cd <REI の写しのフォルダ>
git pull
```

**打つ言葉**（自分のプロジェクトで Claude Code を起動し直してから）：

```text
/rei
```

**起きること**：

- ［機械］起動のときに、写しのほうが新しい版になっていることが知らされます（写しを新しくしていなければ、知らせは出ません）
- ［AI］`/rei` で、AI が状態を読んで、今の版・新しい版・版上げの試しなど、次にすることを選べます
- 版上げの手順（人が進めます）：何をするかの一覧（新しい雛形の側の `scripts/upgrade-plan.sh`）を見て、別の作業フォルダで試してから（`scripts/upgrade-try.sh`）当てます。手順は `docs/howto/upgrade.md`

**気をつけること**：新しい雛形を上から写すと、プロジェクトで書き足したところが消えます。
