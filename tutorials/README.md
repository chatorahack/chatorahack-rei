# チュートリアル（まずこれで試す）

5つの場面を順に試します。1つにつき数分ほどです。題材は作り話です。このフォルダは雛形（`template/`）の外にあり、プロジェクトには写りません。

| 回 | 覚えること |
|---|---|
| [1. 初めての分野の相談](01-first-question.md) | 作り始める前に「既にあるもの」を見せ、決めるのは人に返す |
| [2. 決めたことを残して、あとで覆す](02-decisions.md) | 決めたことは書き換えずに、新しい番号で覆す |
| [3. 「止めて」で止める](03-stop.md) | 止めると、人が印を消すまで AI の道具が止まる |
| [4. コミット前の点検](04-commit-checks.md) | コミットのたびに機械が確かめる |
| [5. 新しい版に気づいて、上げる](05-upgrade.md) | 写しを新しくすると知らせが出る。変わった所だけを当てる |

## 始める前に：試し用のフォルダを作る

**1.〜4. は、本番のプロジェクトでは試さないでください。** 試すと、作り話の決めたことの記録が残ります。コミットした後に書き換えたり消したりしようとすると、コミット前の点検が止めます。

0. このリポジトリを手元に clone します（`git clone <このリポジトリの URL>`。ZIP で取ると、5. の `git pull` が使えません）
1. 試し用の新しいフォルダを、clone したフォルダの**外**に作り、[README](../README.md) の「始め方」の 1.・2. をそのフォルダで済ませます（`template/` の中身を写す、git を始めて名義を決める、`core.hooksPath` を設定する）。中身の写し方は、Git Bash なら `cp -r <clone したフォルダ>/template/. <試し用のフォルダ>/` です（先頭が `.` のフォルダも一緒に写ります）。3.（個人情報の表）と 4.（`AGENTS.md` の記入）は、試しでは飛ばしてかまいません
2. そのフォルダで Claude Code を起動し、「始めます」と話しかけます（起動しただけでは、AI は話し始めません）。AI が `START.md` を一緒に埋めようとするので、「何を作るか」には「REI を試す」、「外の決まり」には「作り話だけを使う試しで、仕事の資料や個人情報は渡さない。外に出すものも無い」と答えれば足ります。「完了条件」も聞かれたら、「チュートリアルを5.まで通す」と答えます。AI が地図や台帳に書く前に「この内容で書いてよいですか」と聞いたら、「はい」と答えて進めます。試しでも、AI に話した内容は使っている AI の提供元へ送られます（[README](../README.md) の「始める前に：外の決まり」）。AI が埋めようとしないときは、「START.md を一緒に埋めてください」と頼みます。最初の起動で出る「新しい版があるかは見ていません」という知らせは 5. で触れるので、そのままで進めます
3. 終わったら、フォルダごと消せます

コマンドは、Windows では Git Bash で打ちます（PowerShell やコマンドプロンプトでは動かないものがあります）。

Claude Code は、ファイルを書く前やコマンドを使う前に、「許しますか」と確認の画面を出します。これは REI ではなく Claude Code の標準の動きで、試し用のフォルダの中のことなら許してかまいません。REI の hook が出す確認には、`[REI decisions-guard]` のように `[REI …]` で始まる理由が付きます。

## 「起きること」の印

各回の「起きること」には、次の印を付けています。

- ［機械］：hook かコミット前の点検が確かめます。hook が動いていて、飛ばす操作（`--no-verify` など）をしていなければ、その場面になったときに、書いてあるとおりに動きます（AI がその操作を試みなければ、その場面は来ません）
- ［AI］：AI への指示（`AGENTS.md`・`policy.md`）による動きです。機械では確かめていないので、起きないこともあります。そのときは、もう一度頼んでください
