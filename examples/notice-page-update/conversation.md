# やり取り — 使用例「お知らせページ改修」

雛形を写したフォルダで、人が3回話しかけたときの、AI の返事と使った道具です。AI が書いた文は、時刻と一部の言葉を見本の形にそろえたほかは、そのまま載せています（道具の結果＝ファイルの中身などは長いので省いています）。

- 作った版：REI 0.3.0-beta.9 の雛形（`template/`）。Claude Code、モデルは Claude Sonnet
- 前もって：`START.md` の「何を作るか」に1行書き、`site/news.html`（トップ画像に代替テキストが無い）を置いた
- 終わった後のファイル：同じフォルダの `project/`

**代替テキスト（alt）の地図**

代替テキストは、画像が見えない人にも画像の役割を伝えるための文字です。スクリーンリーダーで読み上げる人や、画像が読み込めなかった場合が対象です。HTMLでは `<img>` の `alt` 属性に書きます。標準は WCAG（Web Content Accessibility Guidelines）の達成基準1.1.1「非テキストコンテンツ」で、W3C の WAI という団体が解説と判断ツリー（Images Tutorial の decision tree）を公開しています。［推測］私の知識からで、今回URLは開き直していません。

考え方は「見た目の説明」ではなく「その画像がページで果たしている役割」を書くことです。画像は次の3つに分かれます。

| 画像の種類 | altの書き方 |
|---|---|
| 飾りで、なくても内容が変わらない | `alt=""`（空にする。属性自体を省くのは不可） |
| 情報を運ぶ（例：画像内に文字がある） | 画像内の文字や伝えたい内容を書く |
| リンクやボタンになっている | 行き先や動作を書く |

**簡易診断（`site/news.html` を開いて見た範囲）**

- `<img src="images/top-winter.png" ...>` は1つだけで、`alt` 属性がありません。公開前のチェックの指摘どおりです。［実行］
- 画像ファイル `site/images/top-winter.png` は作業フォルダに見当たらず、何が写っているか私は見ていません。そのため具体的な文言は私からは決められません。［実行］（site 内のファイル一覧で確認。画像は別の場所にあるのかもしれません）
- ほかの画像は無く、`width`/`height` は指定済みです。ほかに目立つ問題は見当たりません。［実行］
- 完璧な診断ではありません。ページ全体のアクセシビリティ診断は、チェックツールの結果が要ります。

**最初の一歩**

1. 画像の役割を決めます。冬らしい雰囲気の飾りなら `alt=""` が定番で、お知らせの内容に関係しないなら嘘にもなりません。画像に文字（例：「冬季休業のお知らせ」）があるなら、その文字を alt に書きます。
2. 決まった形を `<img>` に入れます。例を2つ示します。
   - 飾りの場合：`<img src="images/top-winter.png" alt="" width="1200" height="400">`
   - 文字入りの場合：`<img src="images/top-winter.png" alt="（画像内の文字）" width="1200" height="400">`

採用する文言は人間が決めます。画像の役割が分かれば、一緒に文言を詰められます。ファイル自体は、頼まれるまで書き換えません。

**教えてください（2つ）**

1. トップ画像は、飾り（雪景色など）ですか。それとも文字や伝えたい情報が入っていますか。
2. 公開前のチェックは、基準（WCAG の A／AA など）を決めていますか。決まっていれば、その基準に合わせます。

答えを返したので、記録をつけます。
